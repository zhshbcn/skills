# 测试用例 Markdown

根据用户需求设计测试用例，并输出一个 Markdown 文件。Markdown 是测试用例的唯一源文件，供评审、版本管理和后续导图转换使用。

## 工作流程

1. 阅读需求，按模块 → 测试点 → 用例组织，覆盖正常流程、边界值、异常和逆向场景。
2. 按“Markdown 格式”写入 `<功能>_测试用例.md`。用户未指定位置时，输出到当前工作区且不覆盖现有文件。
3. 生成前完成“自检”。修复发现的问题后再交付。
4. 报告文件的绝对路径和用例统计（按 #0～#3 分级）。如用户还需要导图，建议使用 `testcase-markdown-to-xmind` 将该 Markdown 转换为 `.xmind`。

## 用例规则

- 层级固定为：`需求 → 模块 → 测试点 → 用例 →（前置条件 / 步骤）→ 预期`。
- 所有前缀的冒号使用全角 `：`。
- 用例等级数字越小越高：`#0` 核心冒烟、`#1` 主流程与重要分支、`#2` 一般场景与异常、`#3` 极少触发场景。
- 每个用例至少有一个步骤；建议每个用例至少有一个前置条件。
- 前置条件与步骤都是用例的直接子节点，且所有前置条件位于第一个步骤之前。
- 预期是步骤的直接子节点。每个步骤可按需包含预期，最后一个步骤必须至少包含一条预期。

## Markdown 格式

用标题深度表达节点层级，不要用列表或段落代替节点：

```markdown
# 需求：用户登录

## 模块：账号密码登录

### 测试点：正常登录

#### 用例：正确的账号密码登录成功#0

##### 前置条件：用户 user01 已注册且状态正常

##### 步骤：输入正确的账号和密码，点击登录

###### 预期：登录成功，跳转到系统首页
```

多个步骤使用同级 `##### 步骤：` 标题；最后一个步骤下至少有一条 `###### 预期：`。一个文件仅包含一个 `# 需求：` 根节点；独立需求分别输出单独的 Markdown 文件。

## 自检

- 根节点、模块、测试点、用例、前置条件、步骤和预期均使用规定前缀。
- 每个用例以 `#0`～`#3` 结尾，至少有一个步骤，且建议有前置条件。
- 前置条件在所有步骤之前；预期仅位于步骤下；最后一个步骤有预期。
- 标题层级严格为 `#` 至 `######`，没有跳级或额外包装节点。
